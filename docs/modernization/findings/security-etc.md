## Detalhes dos checks propostos (só D e F)

### `autofocus-without-describedby`
- **Guias**: `passkey-authentication` (o guia de orientação `passkeys` aponta para ele).
- **Gatilho**: nó com `attrs.autofocus` presente e `aria_describedby` ausente ou apontando para id inexistente. Refinar (não obrigatório para o gatilho): `attrs.autocomplete` contém o token `webauthn`, marcando formulário de sign-in com Conditional UI.
- **Evidência**: `input[autocomplete~="webauthn"] com autofocus sem aria-describedby válido (selector: <path>)`.
- **Falso positivo / keepWhen**:keepWhen = presença de `autofocus`. dropWhen = `aria_describedby` referencia nó existente; ou `autofocus` usado fora de formulário de autenticação e o consuming decide limitar o check por `autocomplete~="webauthn"` (recomendado para reduzir ruído).
- **Fallback/Baseline**: `autofocus` e `aria-describedby` são amplamente disponíveis; a detecção de capacidade `PublicKeyCredential.getClientCapabilities()` é "Newly available" desde 2025-02-06 (Chrome/Edge 133, Firefox 135, Safari 17.4) e o guia recomenda `webauthn-polyfills` (com SRI em CDN). O sinal DOM independe do suporte à API — o check continua válido no fallback de senha.
- **Fixture mínima**: `<form><input type="text" autocomplete="username webauthn" autofocus></form>` (deve disparar) e a mesma com `aria-describedby="hint"` + `<p id="hint">…</p>` (não deve disparar).

### `webmcp-form-tool-metadata`
- **Guias**: `agentic-forms`.
- **Gatilho**: nó `form` com `attrs.toolname` definido e `attrs.tooldescription` ausente/string vazia. Opcional: sinalizar `toolautosubmit` em `<form>` com `<button type=submit>` cujo nome sugere ação destrutiva — **não** incluído no gatilho por ser heurística de texto.
- **Evidência**: `form[toolname="search-cars"] sem tooldescription — schema gerado pelo browser fica sem descrição de uso`.
- **Falso positivo / keepWhen**:keepWhen = atributo `toolname` presente (o form é declarado como tool). dropWhen = `tooldescription` não vazio; ou nenhum atributo `tool*` (form comum). Não confundir com `experimentalWebMcpTool` do Angular Signal Forms, que não deixa atributo no DOM.
- **Fallback/Baseline**: atributos `tool*` "não são nativamente suportados por nenhum browser principal" e são ignorados com segurança — o `<form>` continua HTML normal, sem feature detection. Preservar o fallback: o check só diagnostica metadados ausentes, nunca bloqueia o form.
- **Fixture mínima**: `<form toolname="search-cars"><input name="q"><button>Search</button></form>` (deve disparar) e a mesma com `tooldescription="Perform a car make/model search"` (não deve disparar).

### `web-install-manifest-required`
- **Guias**: `install-web-app`.
- **Gatilho**: presença de nó `tag === "install"` **e** ausência de `<link rel="manifest">` no documento (verificado por `attrs.rel`/`attrs.href` nos nós `link`, ou `__document.links` quando disponível). Variante: `<install manifest="…">` com `manifestid` ausente e manifesto sem `id` — exige `__manifest`, fora do gatilho base.
- **Evidência**: `<install> sem <link rel="manifest"> no documento — installresult=invalid-data / DataError esperado`.
- **Falso positivo / keepWhen**:keepWhen = elemento `<install>` renderizado (mesmo que o browser mostre só o child de fallback). dropWhen = manifesto vinculado; ou a página usa apenas `navigator.install()` (não detectável — limitação conhecida); ou nenhuma intenção de instalação.
- **Fallback/Baseline**: Web Install API é progressive enhancement; `<install>` "não é nativamente suportado por nenhum browser principal" e aceita child de fallback (`<install><a href="/install-help">…</a></install>`); manifesto tem suporte limitado (Chrome/Edge/Safari, não Firefox). O check não deve desencorajar o fallback content.
- **Fixture mínima**: `<install></install>` sem `<link rel="manifest">` (deve disparar) e a mesma com `<link rel="manifest" href="/manifest.webmanifest">` (não deve disparar).

### `external-subresource-integrity`
- **Guias**: `secure-external-subresources` (o apêndice SRI de `security` é coberto por referência).
- **Gatilho**: para todo nó `script[src]` ou `link[rel=stylesheet|preload|modulepreload][href]` cuja URL é absoluta e cross-origin em relação a `__document.origin`: disparar se `attrs.integrity` ausente **ou** (`integrity` presente e `attrs.crossorigin` ausente). Opcional (mesma severidade): `referrerpolicy` ausente em recurso de CDN terceira.
- **Evidência**: `<script src="https://cdn.example/ui@2.4.0/app.js"> cross-origin sem integrity/crossorigin (selector: <path>)`.
- **Falso positivo / keepWhen**:keepWhen = URL absoluta com host diferente do documento. dropWhen = URL relativa/same-origin; `rel=dns-prefetch`/`preconnect` (não hasháveis); `data:`/`blob:`; ou tríade `integrity` + `crossorigin` + `referrerpolicy` completa. Nunca inferir "cross-origin" de string absoluta sem `__document.origin` — isso geraria falso positivo em host próprio.
- **Fallback/Baseline**: SRI em `<link>`/`<script>` é "Widely available" (Baseline desde 2017-09-19 para Web Cryptography, suporte universal moderno). Já os modificadores CSS `url()` são "Limited availability": `cross-origin()`/`referrer-policy()` em Chrome/Edge 150 e Safari 26.2, `integrity()` só Chrome/Edge 150 — fora do gatilho; fallback preservado =`<link rel="stylesheet" integrity crossorigin referrerpolicy>` em vez de `@import`, `<meta name="referrer">`/header `Referrer-Policy: strict-origin-when-cross-origin`, e cascata de declarações CSS separadas (nunca `src: url(…integrity(…)), url(...)` na mesma lista).
- **Fixture mínima**: página com `<script src="https://cdn.example/a.js">`, `<link rel="stylesheet" href="https://cdn.example/a.css" integrity="sha384-…">` sem `crossorigin`, e um `<script src="/local.js">` (controle). Esperado: 2 achados, 0 no controle.

### `csp-meta-mandatory-directives`
- **Guias**: `security` (§3.2), `trusted-types` (§4).
- **Gatilho**: `__document.meta` contém `<meta http-equiv="Content-Security-Policy">` cujo `content` omite qualquer uma de: `script-src`, `object-src 'none'`, `base-uri 'none'`, `require-trusted-types-for 'script'`. Emitir um achado por diretiva ausente, com o valor literal do `content` como evidência.
- **Evidência**: `meta[http-equiv="Content-Security-Policy"] sem require-trusted-types-for 'script' (content="script-src 'nonce-abc' 'strict-dynamic'")`.
- **Falso positivo / keepWhen**:keepWhen = existe meta CSP na página (sinal de que a política é expressa no documento e observável). dropWhen = nenhum meta CSP (a política pode vir por header HTTP invisível — **não** reportar "CSP ausente"); `require-trusted-types-for 'script'` presente. **Não** exigir `frame-ancestors` no meta: a diretiva é ignorada em `<meta>` e só vale no header, portanto exigiria falso positivo. Igualmente fora de escopo: HSTS, COOP/CORP, CORS, `Clear-Site-Data`, `X-Frame-Options`.
- **Fallback/Baseline**: CSP é amplamente suportado; Trusted Types é "Newly available" desde 2026-02-24 (Chrome/Edge 83, Firefox 148, Safari 26), com tinyfill `window.trustedTypes = { createPolicy: (n, r) => r }` e rollout `Content-Security-Policy-Report-Only` antes de enforçar. A escada `'strict-dynamic'`/`https:`/`'unsafe-inline'` deve ser preservada — o check não incentiva remover tokens de compatibilidade.
- **Fixture mínima**: `<meta http-equiv="Content-Security-Policy" content="script-src 'nonce-x' 'strict-dynamic'">` (deve disparar 3 achados: `object-src`, `base-uri`, `require-trusted-types-for`) e a mesma com as três diretivas (não deve disparar).

### `lna-insecure-context-delegation`
- **Guias**: `local-network-access`.
- **Gatilho**: nó com `attrs.allow` cujos tokens incluam `local-network` ou `loopback-network` **e** `__env.isSecureContext === false`. (Extensão mínima: um campo booleano global `isSecureContext` em `__env`, lido de `window.isSecureContext` — uma linha global, sem custo por nó.)
- **Evidência**: `iframe[allow~="local-network"] em contexto inseguro — permissões LNA são negadas automaticamente`.
- **Falso positivo / keepWhen**:keepWhen = token LNA explícito no `allow`. dropWhen = `isSecureContext === true`; página servida de `http://localhost` (é loopback, mas contexto seguro — isSecureContext já resolve); nenhum token LNA. Não tentar inferir a origem de rede do dispositivo a partir do URL — isso exigiria DNS/header, fora do snapshot.
- **Fallback/Baseline**: LNA é "Limited availability" (Chrome/Edge 145; Firefox/Safari sem suporte). Fallback obrigatório a preservar: `try/catch` em `navigator.permissions.query()` tratando nome desconhecido como `'prompt'`, **nunca** consultar o legado `local-network-access` (quebra o renderer em Chrome antigo), e tratamento de `TypeError`/`AbortError` com UI de remediação. O check apenas sinaliza o requisito de secure context.
- **Fixture mínima**: servir `<iframe src="https://setup.example/bridge" allow="local-network; loopback-network">` em `http://` (deve disparar) e a mesma em `https://` (não deve disparar).

### `email-verification-token-field`
- **Guias**: `verify-email-ownership`.
- **Gatilho**: nó `input` com `attrs.autocomplete === "email-verification-token"`. Disparar se: `attrs.nonce` ausente/vazio, **ou** o `path` do nó não compartilha um ancestral `form` com outro `input[autocomplete="email"]`. Sinalizar ausência de `<meta http-equiv="origin-trial">` em `__document.meta` como evidência adicional, não como gatilho isolado (trial pode vir por header `Origin-Trial`).
- **Evidência**: `input[autocomplete="email-verification-token"] sem nonce ou fora do <form> do campo email (selector: <path>)`.
- **Falso positivo / keepWhen**:keepWhen = token de verificação de e-mail presente (o autor adotou EVP). dropWhen = `nonce` não vazio e mesmo `<form>` do campo `autocomplete="email"`; ausência do input (página usa OTP clássico, que é fallback legítimo). **Não** exigir meta `origin-trial` sozinho: o token pode ser entregue por header.
- **Fallback/Baseline**: EVP é progressive enhancement sobre OTP/magic link e opera via Origin Trial; em browsers sem suporte o input é ignorado e o form envia `token=""`. O servidor deve degradar para e-mail tradicional — o check não deve recomendar bloquear cadastro quando o token estiver vazio. Preservar também `Cache-Control: no-store` e nonce em session state (servidor, fora do snapshot).
- **Fixture mínima**: `<form><input type="email" autocomplete="email"><input type="hidden" autocomplete="email-verification-token"></form>` sem `nonce` (deve disparar); mesma com `nonce="…"` (não deve disparar); e um form separado só com o token (deve disparar pela regra de mesmo form).

### `manifest-migration-metadata`
- **Guias**: `migrate-web-app-origin`.
- **Gatilho**: `__manifest` (nova facet: conteúdo do manifesto referenciado por `<link rel="manifest">`, buscado e parseado apenas quando same-origin) com array `migrate_from` não vazio e `id` ausente — o guia exige "The new app must have an `id`". Variante: `migrate_to` presente sem `install_url`.
- **Evidência**: `manifesto de <link rel="manifest"> declara migrate_from sem id — migração não pode ser verificada`.
- **Falso positivo / keepWhen**:keepWhen = `__manifest` disponível e `migrate_from`/`migrate_to` presentes. dropWhen = manifesto cross-origin (não legível — não reportar falso "ausente"), fetch bloqueado, ou nenhum membro de migração. O arquivo `.well-known/web-app-origin-association` do origin antigo é server-side e fica fora do check.
- **Fallback/Baseline**: Chrome/Edge 149, sem Firefox/Safari. Fallback a preservar: banner de reinstalação manual no origin antigo; dados e permissões **não** migram. Custo: uma passada CDP/fetch adicional por página, somente quando há `<link rel="manifest">` same-origin.

## Resumo da fatia

- Contagens: D=3 F=6 N=26 E=0 (total 35).
- Top 5 oportunidades priorizadas (impacto × custo):
  1. `external-subresource-integrity` — maior impacto (supply chain/XSS por CDN) com custo baixo: só `attrs` opt-in + `__document.origin`.
  2. `csp-meta-mandatory-directives` — cobre XSS/Trusted Types em duas guias com uma única leitura do meta CSP em `__document`.
  3. `web-install-manifest-required` — custo zero (tag + `attrs` existentes) e evita `DataError` previsível na instalação.
  4. `webmcp-form-tool-metadata` — custo zero (`attrs` no `<form>`), diagnostica metadado obrigatório ausente em API emergente.
  5. `email-verification-token-field` — impacto médio-alto (fluxo de cadastro), custo baixo (`attrs` + `path` + meta), com fallback OTP bem definido.
- Guias que exigem novas facets, agrupados por facet:
